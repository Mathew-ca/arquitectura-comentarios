Modelo-Vista-Controlador es uno de los patrones más antiguos para organizar interfaces de usuario. El modelo contiene los datos y las reglas, la vista se encarga de mostrarlos y el controlador recibe las acciones del usuario y coordina a los otros dos. La idea central es la separación de responsabilidades: cambiar el aspecto de una pantalla no debería obligar a reescribir la lógica.

En las aplicaciones web tradicionales del lado del servidor, el controlador recibía la petición, consultaba el modelo y elegía una plantilla para generar el HTML. Frameworks como Rails, Django o Spring popularizaron esta forma de trabajar, y todavía hoy es una estructura muy sólida para aplicaciones con mucho contenido y formularios.

Con las aplicaciones de una sola página, las fronteras se difuminaron. Vue, React y otras librerías organizan la interfaz en componentes que combinan estado, lógica y presentación en unidades pequeñas y reutilizables. Surgieron variantes como MVVM, donde un modelo de vista expone datos que la interfaz enlaza de forma reactiva.

Aunque los nombres cambien, la pregunta de fondo sigue siendo la misma: dónde vive cada responsabilidad. En un proyecto Nuxt, por ejemplo, conviene mantener los componentes enfocados en mostrar, y mover la obtención de datos y las reglas a composables o a rutas del servidor, para que cada pieza se pueda entender por separado.
