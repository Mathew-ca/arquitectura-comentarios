La arquitectura hexagonal, también llamada de puertos y adaptadores, propone colocar la lógica de negocio en el centro del sistema y mantenerla libre de detalles técnicos. El núcleo no sabe si los datos se guardan en PostgreSQL o en un archivo, ni si las peticiones llegan por HTTP o desde una cola de mensajes.

Para lograrlo, el núcleo define puertos: interfaces que describen lo que necesita del mundo exterior, como «guardar un pedido» o «enviar una notificación». Los adaptadores son las implementaciones concretas de esos puertos, por ejemplo un repositorio que usa SQL o un cliente que llama a un servicio de correo. Cambiar de tecnología significa escribir un adaptador nuevo, sin tocar las reglas de negocio.

El beneficio más inmediato es la facilidad para probar. Como la lógica no depende de infraestructura, se puede verificar con pruebas rápidas que usan adaptadores falsos en memoria. No hace falta levantar una base de datos para comprobar que un descuento se calcula bien.

Eso sí, no es gratis. Introduce más interfaces y más archivos, algo que en una aplicación pequeña puede resultar excesivo. Conviene aplicarla cuando la lógica de negocio es realmente rica o cuando se prevé que las tecnologías de entrada y salida van a cambiar con el tiempo.
